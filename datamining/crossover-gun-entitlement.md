---

User's idea: a hidden secret might be gated behind an **online-service round-trip** (one system flags something on the Social Club/ROS service, another reads it to validate/unlock) rather than script-calls-script. Motivating real example: the **Double-Action Revolver** crossover (unlocked by a GTA Online treasure hunt, granted in RDR2). First-hand findings from the script corpus (ScriptDiag grep + native census):

- **The gun itself:** weapon model `w_revolver_doubleaction01`; sold by `shop_gunsmith.ysc` (which carries its `SALES_PITCH_DOUBLE_ACTION_REVOLVER_A/B` audio) via the **generic** shop owned/unlock UI state machine (`SHOP_H_OWNED`/`SHOP_H_NEEDS_UNLOCK`/`SHOP_H_CANT_UNLOCK`/`STAMP_UNLOCKED_RANK`). **No bespoke crossover script exists** — it rides the ordinary catalog/award path. (The "lowry" grep hits were the NPC `EdmundLowry`, not Lowry's Revolver — dismissed.)
- **The mechanism = ITEMDATABASE "award" system + ROS/Social Club entitlement**, entirely data-driven:
  - Every `shop_*` (incl. gunsmith) calls `_ITEMDATABASE_GET_AWARD_INFO` (26 scripts) to read award/unlock status. RDO's fuller path `_ITEMDATABASE_FILLOUT/GET_AWARD_UNLOCK_FLAG(_COUNT)` is used **only** by `role_progression.ysc`. `ITEMDATABASE_IS_BUYABLE_AWARD_VALID` in 110 scripts.
  - Entitlement/credential layer: `NETWORK_HAS_ROS_PRIVILEGE` (net_main/startup/tg), `NETWORK_HAS_VALID_ROS_CREDENTIALS` (player_menu), `_AWARDS_GET_UNLOCK_CLAIM_DATA` (startup_mp/startup_tlg), plus **engine events** `EVENT_NETWORK_SOCIAL_CLUB_ACCOUNT_LINKED` and `EVENT_NETWORK_NETWORK_ROS_CHANGED` (from strings.txt).
  - `DLC::_GET_SPECIAL_EDITION_*_BONUS_ENABLED` (the pre-order Special Edition bonus checks) is sprinkled across 400–530 scripts — ubiquitous, not crossover-specific.
- **Award definitions live in the `catalog`/item-database metadata, NOT in scripts** (strings show a large `award_bundle_*` set and a `catalog/*` UI/flow tree). So the "flag" is set server-side (by GTA/ROS); RDR2 scripts only ever **read** it through the shared ITEMDATABASE award natives. This confirms the user's round-trip intuition as the real mechanism **but refines it**: you will NOT find a "script A flags → script B reads" pair inside RDR2 — the flag isn't in the scripts, and the read is one centralized native call.

**Implication for mystery-hunting (the promising next axis):** if hidden content were gated behind an entitlement/award, it would surface as (a) an **award/catalog item in the item-database metadata that maps to no publicly-known unlock**, or (b) a script reacting to `EVENT_NETWORK_SOCIAL_CLUB_ACCOUNT_LINKED` / an award check in an unusual way. Concrete next step = enumerate award items + their unlock flags from the catalog/itemdatabase data files (is CodeX able to parse the RDO `catalog` format? — unverified) and diff against known unlocks, the same shape as the timeFlags/nested scans but on the entitlement axis.

**External research + first-hand verification of its leads (2026-07-23):** research (Halen84 1491.50 decompile + alloc8or DB) confirmed the mechanism and named the natives: SP grant reads an **online award claim** (`NETWORK_AWARD_HAS_REACHED_MAXCLAIM` 0xFBE782B3165AC8EC → `_AWARDS_GET_UNLOCK_CLAIM_DATA` 0xB9467E41DAB1CF2C → `_ITEMDATABASE_FILLOUT_AWARD_UNLOCK_FLAG` 0x8D029948CA29409B); RDO uses `UNLOCK::UNLOCK_IS_UNLOCKED` 0xC4B660C7B6040E75; weapon-variant plumbing is `WEAPON::_GET_WEAPON_UNLOCK`. **No `ENTITLEMENT`-named native exists** — in RDR2 an entitlement check IS an award/unlock check. Requires linked Social Club account (`NETWORK_HAS_SOCIAL_CLUB_ACCOUNT`), gift delivery via `SOCIALCLUB::SC_INBOX_*`. Research flagged an award-claim in `startup.c` on award id `1377133516`/**0x521563CC** but couldn't prove it's the revolver.

First-hand census (native-call census) + a constant look-up pass verified and REFINED this:
- Caller counts: `NETWORK_AWARD_HAS_REACHED_MAXCLAIM` 153; `UNLOCK_IS_UNLOCKED` **1,342** (everyday unlock check); `_GET_WEAPON_UNLOCK` 1,066; `_AWARDS_GET_UNLOCK_CLAIM_DATA`/`SC_INBOX` only `startup_mp`/`startup_tlg`; `NETWORK_HAS_SOCIAL_CLUB_ACCOUNT` 3; `_ITEMDATABASE_FILLOUT_AWARD_UNLOCK_FLAG` only `role_progression`.
- **Award id 0x521563CC is a GENERIC award, NOT the revolver** — x1 in `startup`/`startup_mp`/`startup_tlg`, x4 in ~40 MP scripts (all shop_* MP, flow_controller MP, fm_*/net_* controllers). A baseline MP award-claim gate, not crossover-specific. The research's award-id lead is a red herring for the gun.
- Double-action **weapon-type** hash `0x0797FBF5` (joaat `weapon_revolver_doubleaction`) in ~250 mission scripts (loadout/spawn refs; x10 each hints at a possible joaat collision, not chased); **model** hash `0x7890B0E7` (`w_revolver_doubleaction01`) in 7 (laramie1, long_update, fm_mission_controller, def_comp_brain, rcm_*).

**Conclusion (verified):** RDR2 scripts only READ awards/unlocks via shared natives; the crossover award→item mapping is **not a bytecode constant** — it lives in the item-database/catalog metadata. No flag-then-validate script pair exists in RDR2. Next concrete step for the entitlement-gated-content hunt = check whether CodeX can parse the RDO `catalog`/item-database format, then enumerate award items + unlock flags and diff vs known unlocks. Harness gained a `const <hex…>` mode (which scripts embed a given u32).
